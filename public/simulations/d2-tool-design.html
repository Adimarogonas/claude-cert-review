Designing the MCP Tool Layer

ShipMind's agents query shipments, adjust routes, and file carrier claims through an internal carrier API exposed over MCP. Your tool granularity, naming, error shape, tool_choice, and agent scope decide whether selection is reliable, recovery works, and writes stay safe.

Tool-layer configuration

Tool granularity

Status and billing as get_shipment_status / get_shipment_billing, or one get_shipment(mode=…).

Naming & descriptions

Descriptions are the primary signal the model uses to pick a tool.

A transient 503 must be distinguishable from a permanent failure.
This step must produce a tool call to yield structured output.
Static carrier reference catalog

The carrier-code & service-level catalog is large and static. An MCP resource is read into context once; a lookup_catalog tool gets called again on every shipment.

The carrier record has 60+ fields; the task needs ~6 (status, ETA, last_scan, exception_code…).
Analyst agent scope

The analyst answers read-only questions; only the dispatcher should mutate state.

How this simulation works

  1. Set the tool-layer choices on the left.
  2. Press Run. The metrics and consequence log respond deterministically.
  3. Each gotcha visibly degrades a metric and turns it red. Find the config that maximizes selection accuracy and recovery while keeping unsafe-write risk at zero.
  4. Open Architecture to see which tool is flagged, then Knowledge Check to test the gotchas.
