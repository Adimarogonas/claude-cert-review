Multi-Agent Research System

A coordinator delegates a research topic to specialized subagents — web search, document analysis, synthesis, report. Configure how it orchestrates them, then watch coverage, attribution, wall-clock time, context-bleed and token cost respond to each decision.

Coordinator configuration

Subagent context

Subagents start fresh; the Agent-tool prompt is the only channel. Sharing the full coordinator history bleeds one subtopic into another.

Execution

Independent subtasks have no data dependency — parallel drops wall-clock from sum-of-tasks to max-of-tasks.

Subagent selection

Routing every query through all four agents burns tokens on simple questions.

Decomposition

Narrow decomposition assigns only some domains — the rest are never researched.

Subagent loop termination

stop_reason is the canonical termination signal, with a turn cap only as a backstop. Parsing text for "DONE" is model-phrasing dependent; a fixed cap as the primary signal cuts loops off mid-research or burns extra turns.

Publish gate (before writing report to production)

Publishing to a shared/production destination is irreversible. A PreToolUse hook on the publish tool blocks it deterministically until review passes. A prompt instruction or a reviewer agent that can be talked around both have a non-zero failure rate — unreviewed reports reach production.
Off → claims arrive at synthesis without source URLs, dates or excerpts, producing unattributed report statements.

Hub-and-spoke — coordinator orchestrates subagents

Every result flows through the coordinator, which passes explicit context in each Agent-tool prompt; the finished report is then handed to a production destination through a publish gate. Red marks the anti-patterns: a direct subagent→subagent edge (bypasses the hub), a shared-context leak (cross-topic bleed), and a publish gate enforced by anything other than a deterministic PreToolUse hook. None belong in a clean hub-and-spoke.

How this simulation works

  1. Set the coordinator configuration on the left.
  2. Press Run. The deterministic model maps each choice to metrics and logs the consequence.
  3. Sound choices push coverage and attribution up; the gotchas degrade metrics and turn red.
  4. Open Architecture to see the hub-and-spoke pattern and its anti-patterns, and Knowledge Check to test the gotchas.
