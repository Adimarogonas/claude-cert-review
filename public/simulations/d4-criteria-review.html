High-Stakes Classifier: Criteria & Review

You are wiring up a classifier that flags policy-violating support messages for refund-eligibility review — a high-stakes decision. Tune the prompt criteria and the review pipeline, then watch the false-positive rate, coverage, consistency, and reviewer agreement respond.

Configuration

Vague prompts ask the model to self-judge; explicit categorical criteria define exactly what to flag vs skip.
High-stakes decisions warrant a second review before the decision is final.
A reviewer that carries the generator's reasoning context inherits its blind spots.
A constrained enum (e.g. flag | skip | unclear) via a tool-use JSON schema guarantees an in-vocabulary verdict; parsing prose yields off-vocabulary, unparseable labels.
At high, latency-tolerant volume the Message Batches API plus prompt caching of the stable rubric/system prefix cuts cost and avoids throughput blowout.

How this simulation works

  1. Set the four configuration controls on the left: criteria specificity, few-shot examples, review passes, and reviewer type.
  2. Press Run. Each choice writes a plain-English consequence and moves the metrics deterministically.
  3. Drive the false-positive rate below the 15% trust threshold while keeping recall, consistency, and reviewer agreement high.

Red means a metric crossed into failure: high false positives, a single pass that misses errors, or self-review confirmation bias.
