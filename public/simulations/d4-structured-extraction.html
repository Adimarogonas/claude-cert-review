Structured Data Extraction

An extraction pipeline reads heterogeneous documents (contracts, invoices, filings) and must emit validated JSON for downstream systems. Tune the output method, schema design, and validation loop, then watch which choices fabricate, leak, or self-correct.

Pipeline configuration

Forced tool use sets tool_choice: "any" — the model must call an extractor, never returns plain text. Prose-parse fishes JSON out of free text.

Restrict categorical fields (e.g. doc_type) to a fixed vocabulary, validated programmatically.

When a date or ID may not exist in the source, required fields structurally pressure the model to invent a value.

On failure, resend the document, the failed extraction, and the exact error so the model self-corrects.

Check relationships strict schemas can't see — line items summing to total, start date before end date.

Define each field precisely — what counts, what to skip, what "absent" looks like. Vague descriptions (e.g. "party": "the relevant party") drive mis-extraction and invented fields.

For a very large corpus, the Message Batches API with prompt caching of the stable schema/system prefix cuts cost and lifts throughput. Note: the Batches API can't run multi-turn tool-call loops mid-request.

Extract → validate → retry loop

Forced tool use with tool_choice: "any" guarantees structured output and kills JSON syntax errors. Validation still has to catch semantic errors — out-of-vocabulary enums, impossible date ordering, totals that don't sum — and feed specific errors back on retry. The two red paths are the gotchas: prose-parsing (malformed output) and required-for-absent fields (fabrication).

required date → model invents a value to satisfy the schema  ·  nullable date → model returns null honestly
tool_choice: "any" → always a tool call  ·  tool_choice: "auto" / prose → may return plain text

How this simulation works

  1. Set the pipeline configuration on the left — output method, schema design, and the validation loop.
  2. Press Run and read the metrics and the per-choice consequence log.
  3. Find the configuration that maximizes valid output and drives fabrication to zero. Watch for the red paths.
