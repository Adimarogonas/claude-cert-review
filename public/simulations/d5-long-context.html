Long-Context Conversation Manager

A multi-turn legal-document analysis session runs long and the context window fills. Choose how you manage context, position findings, and offload exploration — then run the session and watch which early facts survive.

Configuration

Context strategy
How history is condensed as the window fills. A persistent structured fact-block keeps amounts/dates anchored in every request, outside summarized history.

Place key findings first and label sections to fight the "lost-in-the-middle" position effect.

Isolate verbose discovery in subagents and persist findings to scratchpad files instead of cramming everything into the main context.

Cache the unchanging 180-page document prefix so it isn't re-sent and re-billed each turn, and trim verbose tool dumps (45-field lookups) to relevant fields before appending. Off means re-sending the full uncached prefix and pasting raw tool output — faster context growth and higher cost.

Human-review routing
How extracted facts reach the answer. A calibrated threshold (tuned on a labeled validation set) routes genuinely uncertain extractions to a human reviewer. Self-reported confidence is uncalibrated — the model can be confidently wrong. Auto-shipping trusts every extraction unreviewed.
Longer sessions accumulate more tool output and history, pushing the window toward overflow.

Context-window fill & summarization

Each cell is one turn. The summary fold compresses early history; a persistent fact-block sits outside it so anchored facts survive. Cells flagged in red are facts dropped when the window overflows under naive truncation.

How this simulation works

  1. Pick a context strategy, toggle lead summaries and subagent offload, and set the session length.
  2. Press Run session. Context usage climbs turn by turn; the meter turns red over 85%.
  3. Watch the early-facts ledger: see which facts survive and which get dropped (red).
  4. Aim for high fact retention, zero lost facts, and a context meter under budget.
